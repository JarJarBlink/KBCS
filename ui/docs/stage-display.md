# ステージDBの表示と共通設定

## 画面とデータの流れ

- ステージ詳細 `/pages/stage-detail/?map=N000` では「詳細表示」「F表示」「敵ステータスを表示」を個別のチェックボックスで切り替える。再アクセス時の表示モードは通常。マップ名とステージ名はそれぞれの表の見出しに置き、冠は全ステージで共有する。
- `display-data.js` の `loadStageDisplayMap` は検索索引と選択マップの詳細を照合し、敵・キャラ索引とともに返す。候補を切り替えたときは既存の `loadStageVariant` で1面だけを差し替える。冠・表示モード・編集プレビューでは取得済みのマップを使用する。
- `display-fields.js` はゲームデータを登録済みの表示項目へ渡す。`display-raw.js` は正式列名と元の位置を対応させる。既存の `view.js` の出撃準備用入口と、出撃制限、特殊ルール、EX、報酬画像、固定編成の組み立てを共用する。
- `display-sheet.js` の `mountStageSheets` は実ページとエディターで使用する。ステージごとに見出し、基本、メディア、報酬、出典、敵の行グループを持つ。DOMが同じ場合は差し替えを省き、冠や表示モードの変更で背景・BGMを作り直さない。元データを見ている場合は折りたたみ状態を復元する。
- XP・素材・報酬判定は既存の `calculateNative` へ送り、入力が同じ結果を共用する。敵のステータスは既存の `prepareEnemyStatistics` で準備する。描画リビジョンを照合し、旧冠や旧候補の結果が現在の表示を更新しないようにする。保存画像は表示中のモードのシートを対象にし、敵表のスクロール幅を保存用の複製だけ広げる。

## 標準設定とプリセット

標準のラベル・順番・表示条件・幅・説明・揃え・強調は [display-defaults.json](../src/features/stages/display-defaults.json) に置く。標準の数値は左揃え。設定の「見た目」から「DBの表示設定」を開き、検索して選んだ実ステージを冠・通常/詳細・秒/F・敵ステータスを変えながら確認できる。

`display-settings.js` の `displayConfiguration` はレジストリ初期値、標準JSON、個人差分を順に適用する。個人設定は `kbcs:database-display:stages` に保存する。`schemaVersion: 1`、`database`、`activePresetId`、`presets` を持ち、各プリセットは ID・名前・変更属性 `overrides`・グループ内順序 `orderOverrides` を保持する。標準プリセットの ID は `standard`。表示モードの通常/詳細はこの保存領域に含めない。

標準値に戻した属性は個人差分から外す。未指定の項目は標準順で最も近い先行項目の直後に挿入し、個人が並べた項目の相対順を保つ。同順は ID で決める。廃止項目は警告を表示して読み飛ばす。改名は `aliases` で対応し、`stage.maxEnemies` は `stage.enemyLimit` へ移行する。設定が破損している場合は標準で開く。

エディターの「保存」で個人設定を確定し、「取消」で最後の保存状態に戻る。JSON入出力では個人設定一式、単体プリセット、開発者標準を選ぶ。開発者モードで出力したJSONをレビューし、標準ファイルを差し替える。書き出し順は ID 順。時間系の表示単位は、レジストリで許可した秒/F/画面指定から選べる。

ステージ詳細で「詳細表示」を有効にすると、横に「詳細表示設定」が出る。選んだ項目IDはブラウザの `kbcs:stage-detail:hidden-fields` に保存する。`stage-detail.js` が選択中のプリセットを解決してから、詳細表示の場合だけこれらの項目を除く。マップを跨いで設定を使い、通常表示とDB表示プリセットでは元の項目が使われる。

## キャラ・敵DBへの適用

対象DBのレジストリと標準JSONを用意し、`displayConfiguration` に DB ID、フィールド群、標準設定を渡す。フィールドは固定ID、グループ、値取得関数、許可する整形を持つ。`data-sheet.js` の `sheetRows` は値の採否を判定してから2組ずつ配置し、余りは全幅になる。`columnTable` は有効なレコードの有無を列単位で判断する。DB固有の複合ブロックは `sheetRow` に渡す。実ページとエディターの双方から同じ表示アダプターを呼ぶ。

画面に渡す値は text、登録済みレンダラーが生成したHTML、欠損等の状態のいずれか。エディターが扱うラベル・説明はプレーンテキスト。`sourceOnly` は詳細の出典へ、`whenActive` は通常表示で有効値だけを表示する。状態には未収録・無効・対象外・未確認・未対応がある。罫線と行構造は共通の `data-sheet.css` が管理する。

設定画面、JSON、CSS、JSは既存の `include_dir!` から配信する。`sync-ui.py` は上流を読み取り専用で扱い、ステージ側のJS・CSSを保持して共通依存をたどる。このページと共通設定のファイルは上流コピーの対象外。

116列の対応と挙動の検証境界は [列対応台帳](../../crates/kbcs-data/docs/stage-columns-v3.md) を参照。

## ステージ詳細の表示規則

- `mapDisplayContext` は `Map_option.csv` の難易度マスクをバッジへ変換する。マップではバッジの範囲と収録小数値の範囲を併記する。ステージでは小数値の整数部に対応するバッジがマップに存在するときに併記する。JP 15.7.4の両方がある5,870面はすべて一致した。
- `mapPoints` は同じイベントPt説明をマップ表へ1回だけ表示する。異なる説明がある場合は対象ステージへのリンクを各説明に付ける。旧プリセットにステージ側のイベントPt指定がある場合は、他の設定を保持したままその項目を読み飛ばす。
- 獲得XPセルの「計算条件」からクリア済み回数・コンボ・おかめはちもくを変更する。適用時は既存のXP計算へ渡し、基礎値は詳細の元データで確認できる。発生間隔は最小値と最大値を併記する。
- 背景・城・BGMの見出しに基本情報と同じ背景色を使う。ステージ詳細のBGM欄は横線1本で上下2枠に分け、1曲の場合は下の枠を空欄にする。各曲はタイトルと城体力条件、再生とシークと時刻の2段。切替値以下を2曲目、それより上を1曲目に記す。再生ボタンと時刻に必要な幅を確保し、残りの幅は再生バーに使う。メディア欄全体が444px未満ではBGM欄を背景・城の下へ移す。初期表示の音源取得は同じBGM IDのプレーヤーで共有する。
- 敵出現表は敵ID・アイコン・敵名を独立した列に持つ。`spawnIcon` はボス指定のある出現行で「Boss」をアイコンの右下に重ね、リンクの読み上げ用ラベルにもボスを含める。倍率はステージ内に体力と攻撃の差があるときだけ副見出しを表示し、差がある行に2値を並べる。列の内容を途中で折らず、幅が足りない場合は既存のフォーカス可能な `data-sheet-scroll` 内で横にスクロールする。
- `castle` は通常城にヘッダー値、個体の城に既存のネイティブ敵体力計算を使う。HUDは敵城の無敵フラグで7個の疑問符を描く。初心の間（T000）は `表示：??????? / 100`、PR000のダミー城は `表示：??????? / 10`。表示上限99,999,999との差分がある場合も内部値と併記する。根拠は `00aa40a8`、`00a9b3e4`、`actor_battle.inc` の `health` と `battle-screen.js` の描画。
- 通常の出撃は「統率力」、アイテム消費は「出撃コスト」。B系列ではネコビタン種別と個数、明示アイテム経路では原本アイテムIDを名前に解決して個数を表示する。判定条件は列対応台帳に記録する。
- 通常比較方式−1で唯一の候補がID 1のトレジャーレーダー1個、比較値0なら、クリア報酬の欄に返還ありと表示する。JP 15.7.4 ARM64の `005d996c` は通常比較をレーダー使用時だけ100に置き換え、返還フラグに対する処理で `006f23b4(1,1,0)` を呼ぶ。戦闘と報酬のロジックは既存の入口を使用する。
- `dropChances` は JP 15.7.4 ARM64（SO SHA-256 `669438f86b41c10c7a387b96eb1ab5ca82a350bacc89ec06c05f699ec3727590`）の `005d996c` の候補選択を抽選率へ換算する。通常比較は先頭から、不成立の確率に候補の比較率を掛ける。逆襲のカオル君（S078）の比較値30と100は、レーダーなしでは3枚30%・2枚70%。方式1/2は先頭を取得前後で分け、記録が有効な通常マップ・EXで全冠共有/冠別を表示する。方式−3/−4の重みは合計で割り、−3には初回条件を表示する。方式2はbc-eventの `rand2-stage-drop-investigation.md` とも照合した。
- 通常比較から外れる未来編の採点分岐や、原本と取り込み順が一致しない候補は確率を数値化せず、比較値は詳細で確認できる。スコア報酬・クリア回数報酬はそれぞれ元の条件、開発素材は既存のネイティブ計算を使う。
- ステージ検索・詳細は原本から解決した同一の報酬IDを使う。旧ローカルAPIのプレビューでは、持ち物カタログで既に解決した名称と画像を使う。報酬の索引と素材の内部番号は[データ層の資料](../../crates/kbcs-data/docs/README.md)を参照。

## 確認結果

- v3 JSON、CSV、表示対応表で116キー・同一スコープ内の正式名・列番号・等級・根拠を突き合わせた。JSON・JS・ローカル配信パス、同期保護設定、UTF-8 BOM、表示基盤のNodeテスト3件を確認した。
- 既存のJP 15.7.4データと既存ローカルAPIを用い、Chromiumで N000・PR000・G002・D000 を確認した。通常と詳細の切替、4冠の同期・再アクセス、敵ステータスの独立、素材の入手確率、固定編成、候補選択、イベントPtと固有条件を確認した。1280pxと320pxで確認し、320pxでは濃紺・ダーク・ライトの各テーマで敵表だけを横スクロールできた。320pxからのステージ画像保存は944×1524pxのPNGになった。
- エディターで実データのプレビュー、編集・取消・保存、プリセット複製・改名、実ページへの適用、個人設定JSONの書き出しと再取り込み、未対応版JSONの拒否、開発者標準の書き出しと秒/F設定を確認した。
- `kbcs-data` は既存依存を再利用してテストコードを含めて型検査した。Windows環境のclang未検出と代替リンカーの異常終了により、新しいRustテストバイナリと配布版は未実行。次回のビルド環境では `cargo test -p kbcs-data map_options_keep_new_columns_and_legacy_annotation` と、新しい詳細APIにおける20列の旧版・21列の新版の原本参照を確認する。全体ビルド、全アセット再取り込み、ネイティブの追加解析は今回の検証範囲外。
- 注釈対応では、ローカルChromiumの1,760px・700px・320pxでPR000を表示し、幅上限1,080px、左揃え、開閉口と表の非重複、BGM初期取得、XP条件適用、詳細切り替え時のマップ再取得なしを確認した。T000の城体力、B000とS434の消費アイテム、N000の冠倍率・統率力・通常報酬を確認し、表示基盤と出撃準備の既存Nodeテストを実行した。
- 追加注釈はPR000とN000を使用し、敵ステータスを出した状態での横スクロール、詳細表示の項目非表示・取消・再読込後の復元、倍率の副見出しとボス判定の条件、1,246px・320pxでのメディア欄を確認した。
- 報酬修正では、実データのS078でチケットの名称・画像と30%／70%、S408で冠別の初回条件、S434で重み抽選、PR000でレーダー返還とアイコン上のBoss表示を確認した。S078の結果は[JDB](https://jarjarblink.github.io/JDB/map.html?cc=ja&type=S&map=78)と一致した。表示基盤のNodeテスト4件とRustの型検査は通過した。新規アイテムの取り込みを検証するRustテストの実行は、Windowsのリンカー異常終了により未確認。

### S095の表示注釈

- `hasAbyssDetail` は互換フラグと面のクリア回数報酬を照合する。JP 15.7.4で両方が一致する11マップを確認した。通常面の下へ別のステージ表を置き、マップの「アビス」から移動できる。面の定義、出現表、計算結果を共用し、回数報酬はアビスの表へ載せる。本家の `005d996c` は別モードの結果経路で `00a0821c` からマップ・面別の回数報酬を読み込む。
- `conditionHtml` は条件ID 1〜9を章クリアにし、種別1の条件をマップや面へ直接リンクする。条件式の原本やサーバー設定は詳細表示の判定内訳に出す。解釈できない条件は原本メッセージまたは条件IDを表示する。
- 固定キャラと進化権の受取済み判定は `006e34b0` で抽選とは別経路。S095のネコウェイを「30%（1回のみ）」と表示する。キャラ報酬は48×38pxのアイコンと名前を縦中央に揃える。「基礎XP / 獲得XP」は原値と計算結果を同じセルで表示する。敵出現表は内容幅で表示し、狭いときは表内で横スクロールする。
- 敵出現表の描画レイヤー・基礎点・味方死亡数条件・城条件と待機保持は、標準設定で通常表示にも出す。体力・攻撃力・DPSは従来の「敵ステータスを表示」で切り替える。
- JP 15.7.4のローカル画面で、S095のアビス、2〜5回目の報酬、章リンク、詳細表示の内訳、3,800 / 17,860 XP、1曲の表示と320pxの敵出現表を確認した。N017で2曲の切替条件、S078で通常の30%／70%、PR000でレーダー返還も確認した。
- 1,242px・320pxのChromiumで、S095（1曲）とN017（2曲）のBGMが横線で上下2枠に分かれ、再生バーが各枠の残り幅を使うことを確認した。

## ステージ検索

- `matchStageQuery` は一致に使った語がステージ名や個別IDに当たったかを返す。`selectStageRows` が全条件を面ごとに判定し、`selectStageMaps` がマップ単位に集約する。マップ単位のステージ名欄は名前・IDに一致した面、該当する面が絞られた場合はその面、1面構成の場合はその面をリンクする。4件以上は4件目以降を展開できる。ステージ単位では両方の名前を毎行表示する。
- マップ名リンクはマップ全体、ステージ名リンクは個別の面を開く。冠は2冠以上を指定している場合に引き継ぐ。出撃用の検索は同じ条件と行を使い、リンク先を出撃準備に切り替える。
- マップ種別は複数選択したいずれか。面番号は表示上の番号で1から始まり、リンク先の `stage` は既存どおり0から始まる。一覧状態は索引の `unlisted` を使う。属性・種族の除外は、OR／AND条件に当たる出現候補が一つでもあれば除外する。敵・属性・背景などの肯定条件は同じ出現候補に当たる必要がある。
- 検索条件は既存の `native-state.js` を使って保存する。従来の単一種別と「選んだ属性のみ」の設定を読み込み、旧ギミック「一覧外」は一覧状態に移す。開催中・開催曜日の判定は既存索引に根拠がないため追加していない。検索項目の参考は[bc-event](https://bc-event.pages.dev/stage/list/)と[JDB](https://jarjarblink.github.io/JDB/map_search.html?cc=ja)。
- ローカルのJP 15.7.4で「大脱走」からN017の第6面への遷移、複数種別と面番号の組み合わせ、属性の除外、一覧外の絞り込み、設定の復元、出撃準備への遷移を確認した。320pxでは結果表内を横にスクロールできる。UIのNodeテスト7件が通過した。
- 絞り込みはマップ種別・敵キャラ・報酬・ギミック・その他の5区画。初期状態ですべて閉じ、同時に開く区画は一つとする。`updateFilterCounts` は見出しに選択件数を出す。敵属性の「除外」と「選んだもののみ」は排他のチェックボックスで、両方を外すと通常の包含検索になる。
- `readFilters` と `writeControls` は読み込みとクリアで共用する。再読み込みでは条件だけを初期化し、詳細から戻った場合は従来どおり復元する。「クリア」は `initializeRewardPicker` が返す表示更新関数で選択済み報酬も消し、既存の索引で結果を1ページ目から描画する。区画の排他開閉、クリア時に文書・索引の要求が発生しないこと、再読み込み、出撃モード、320px幅を実データで確認した。
- ID・マップ名・ステージ名・統率力・難易度の列見出しで昇順・降順を切り替える。IDは内部マップIDと面番号、名前は数字を考慮した日本語の照合順。マップ単位の数値は絞り込み後の昇順で最小値、降順で最大値を使う。ステージ名順ではマップごとに並び替えの基準となる面へのリンクを先頭に表示する。表の単位を切り替えても同じ並び替え条件を使う。
- S095の空の第2枠と敵出現の標準列、N017の2曲と320px幅での区切り、検索5列の両方向とステージ単位への切り替えをローカル実データで確認した。UIのNodeテスト8件が通過した。
