# 戦闘の操作盤・詳細・表示上限

上部の操作盤と下部の詳細を分離する。詳細は「個体詳細」「ステージ」「動作・PC」の3タブ。敵/味方一覧から個体を選ぶと個体詳細を開く。ステージは戦闘APIの城/個体/制限/スコアと出撃時に固定したステージ情報、動作・PCは既存の計測と `/api/runtime` を使用する。KBCSのRAMはホスト分のみ。

個体の生成IDを `focusActor` としてフレーム要求に添付する。選択タブが見えている時だけ要求する。Rustは既存の観測記録から生成IDを解決し、退場していなければ描画ループで個体の本体・登場・魂に対応する命令範囲を記録する。同じ応答の座標を拡大・中央配置してプレビューへ渡す。別時計で先行再生しない。退場した個体は数値を保持し、再利用された枠を描かない。JSONメタデータのみ追加し、KBFレコードとC++ ABIは変更しない。

ログは最大80行で、表示フレーム間のHP・行動・妨害・バリアなどの確定値の差分を記録する。バッチを挟む場合は論理Fの範囲を表示し、その途中の変化や変化の直接原因を断定しない。次の候補は、ダメージ確定と妨害適用を個体ID付きイベントにし、予約量・防いだ量・HPに反映された量を分けること。生の内部値や抽選は開発者向けの別表示を想定する。

描画の初期上限は30 FPS。設定は10～120 FPSの選択肢として保存する。入力は従来どおり即時受付し、描画は共通のゲートで最後の描画から `1000 / 上限` ms を待つ。論理更新は実時間と設定速度から計算し、必要に応じて既存の連続tickをまとめる。描画上限や省略数から論理Fを求めない。1F/10F操作は従来どおりコアの指定更新を使用する。

パーツ省略は既定で無効。任意で有効にすると、WebGL提出直前に個体範囲を後ろから確認する。前面の通常ブレンド・不透明な軸平行パーツが、背面パーツの描画範囲を内側に含むときだけ、対応UVのアルファを確認する。線形フィルタの隣接画素とラスタライズの余白を含め、半透明、斜めの前面パーツ、証明できない組み合わせは描く。小さなアルファ情報を再利用し、初回判定の件数と範囲を制限する。描画命令そのものや順序、HP、乱数、当たり判定は変更しない。GPUの速度改善は機種・場面に依存する。

描画完了時に、実時間上すでに経過したtickがあれば次の要求を直ちに送る。戦闘フレーム要求は1件ずつで、カメラ入力とFPS上限の扱いはそのまま。非表示のステージ情報は更新を休止し、開いた時に最新値を取得する。初回の個体用テクスチャ転送は最大32 MiBまで暗転中に行う。測定は「動作・PC」でWebGL提出、HUD提出、受信後の描画待ちに分ける。WebGL提出時間はGPU実行時間ではない。
